# Session Sidecar · 会话旁录

[HanaAgent / OpenHanako](https://github.com/liliMozi/openhanako) 插件：为每个会话自动维护一份结构化状态档案——**为何开始、做了什么、形成了什么结果、停在哪里、接下来可能要做什么**——无需翻阅对话记录，一眼掌握会话全貌。

## 解决什么问题

会话一多，切回去经常想不起"这个会话当时进行到哪了"。旁录像书签一样挂在侧边栏：你切到哪个会话，它就显示哪个会话的档案。

## 两种展示形态

- **侧边栏挂件**（主要形态）：跟随你正在查看的会话，单会话全字段展示。暖纸感设计，三状态语义色（进行中 / 已搁置 / 已完成），字段级空态与生成中骨架屏，宽度 200~400px 自适应，明暗双主题随宿主自动切换。
- **旁录总览页**：左导航「旁录」入口，所有会话档案的完整仪表盘，支持手动重新生成。

## 它什么时候更新

落定驱动，不是定时刷新：

```
一段工作落定（一条消息完成 / 一个工具执行完）
  → 标记待更新，去抖 15 秒（流式过程中的增量事件不会打断计时）
  → 调度器每 5 秒巡逻，距上次生成超过 90 秒才重新生成
  → 生成前检查消息数，无变化则不调用 LLM（不花 token）
```

**生成模型可换**：默认走宿主当前采样模型；配置自定义 OpenAI 兼容端点后改走该端点（如 Mac Studio 的 OMLX `Qwen3.6-35B-A3B`，本地算力零成本）。请求自动附带 `enable_thinking: false` 关闭 Qwen3 系列的思考模式，并对残留 `<think>` 标签做双重清理，确保输出可直接解析为 JSON。

另有三条补充通道：每 60 秒扫描会话文件修改时间兜底；切到没有旁录的会话会立即触发首次建档（约 20 秒内出现）；Agent 可通过工具随时写入人工备注（即时落盘）。

## 数据模型

每份档案五个字段 + 状态 + 人工备注：

| 字段 | 含义 |
|---|---|
| 缘起 | 这个会话为什么开始 |
| 进展 | 按时间顺序的关键动作列表 |
| 结果 | 目前形成了什么（可能为空） |
| 停在 | 当前停在什么位置 |
| 接下来 | 后续可能的方向列表 |
| 状态 | 进行中 / 已搁置 / 已完成（由 LLM 判断） |
| 备注 | 人工追加的批注（带类型标签，如 decision / risk） |

档案存放在 `~/.hanako/plugin-data/session-sidecar/sidecars/`，每个会话一对 `.json`（结构化）+ `.md`（人类可读），原子写入，纯本地。

## 跟随机制（技术说明）

宿主插件协议目前没有"查询当前会话"的官方 API，且桌面端主界面与挂件 iframe 分属不同源（file:// vs http://），跨域 DOM 读取被浏览器拦截。为解决这个问题，插件会在激活时向宿主渲染器目录注入一个约 50 行的**跟随桥脚本**（`modules/hana-session-follow.js`）：

- 在主窗口顶层每 0.7 秒读取一次"当前激活的会话"，通过 postMessage 广播给插件 iframe
- 注入前自动备份原文件（`index.html.hana-follow-backup`），卸载只需删除一行 script 标签
- 宿主 OTA 升级后插件自动重新注入（读取 artifacts 指针定位新版本目录）
- 桥失效时自动降级为"最近活跃会话"模式，界面明确标注，不会白屏

如果你介意这个机制，可以在设置中不授予插件 full-access 权限——挂件会退化为"最近活跃"模式，其余功能不受影响。

## 安装

1. 在 Releases 下载最新 `session-sidecar-x.y.z.zip`
2. HanaAgent → 设置 → 插件 → 安装本地包 → 选择 zip
3. 授权 full-access（用于读取会话文件、调用宿主 LLM 生成摘要、跟随桥自愈注入）

## 配置项

| 项 | 默认 | 说明 |
|---|---|---|
| 启用旁录 | 开 | 关闭后停止生成，保留已有档案与页面 |
| 去抖秒数 | 15 | 一段工作落定后静止多少秒触发更新 |
| 最小更新间隔 | 90 秒 | 同一会话两次 LLM 生成之间的最小间隔（成本控制） |
| 对话摘录长度上限 | 9000 字符 | 送入 LLM 的最近对话摘录长度 |
| 生成端点（OpenAI 兼容） | 空 | 留空走宿主默认模型；填如 `http://100.70.149.123:10086/v1` 则旁录改用该端点生成 |
| 生成端点 API Key | 空 | 自定义端点的 Bearer Token，如本地 OMLX 的 `1234` |
| 生成模型名 | 空 | 自定义端点的模型 ID，如 `Qwen3.6-35B-A3B` |
| 记录事件总线调试日志 | 关 | 开发诊断用 |

## Agent 工具

- `sidecar_status`：查询某会话（默认当前会话）的旁录内容
- `sidecar_note`：向旁录追加人工备注（类型 + 文本），适合记录关键决策与口径

## 隐私

全部数据存储在本地 `~/.hanako/plugin-data/` 内，不发送任何数据到外部。摘要生成调用的是你在宿主中自行配置的模型服务。
